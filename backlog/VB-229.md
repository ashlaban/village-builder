# VB-229: Refactor: events in the kernel, and land's memories as their first subscribers
Status: ready
Priority: 3
Size: S
Design ref: none (code structure). `docs/architecture/target-v2.md`, section 3.2 (events; Kim's decision 25) and 4.1 (Workflows, rule 4).
Goal: A lower layer's act reaches a higher layer by an event (Kim, 9 November): the lower module emits, higher modules subscribe at load and run at once, in load order, and cannot veto. Today five calls go the wrong way instead: `sim/stakes`, `sim/territory` and `sim/herds` call `remember`, and `sim/claims` calls `tieOf`, in `sim/relations`. Build the channel with these as its first use.
Acceptance criteria:
- [ ] A kernel module (in `sim/records`, or a new `sim/events` loaded before every emitter) gives `on(kind, fn)`, at load only and sealed with the registries, and `emit(st, kind, data)`, which calls the subscribers at once in the order they registered. Subscribers are code and never enter `st`; `emit` allocates nothing beyond its caller's `data`.
- [ ] `sim/stakes`, `sim/territory` and `sim/herds` emit (a claim taken, a border lost, a bull lent) where they called `remember`; `sim/relations` subscribes and writes the same memories at the same point in the step, so the golden file holds.
- [ ] `sim/claims` no longer imports `sim/relations`: what it took from `tieOf` is passed in by its caller, or asked through a read that needs no import. If neither fits without a behaviour change, leave it and say why in the notes.
- [ ] `tools/writes.js` (or `tools/rules.js`) lists every event kind with its emitters and subscribers; a kind with no subscriber, or a subscriber to a kind nothing emits, fails `npm test`.
- [ ] A subscriber that issues a command and is refused changes nothing further (target-v2 4.1, Workflows, rule 4): a test shows it.
- [ ] Refactor rules of `BACKLOG.md`: behaviour unchanged, `tests/golden.json` and `tests/counters.json` unchanged, `npm run verify`'s hard checks pass, its targets reported with their residuals.
Notes:
