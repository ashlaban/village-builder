# VB-232: Refactor: a rule's contribution is registered by its source
Status: ready
Priority: 3
Size: S
Design ref: none (code structure). `docs/architecture/target-v2.md`, section 4.1 (the rules registry).
Goal: The registry's list of contributions is how upward influence is listed (target-v2 3.2), but `source` is a label no one checks: the `hunger` and `frailty` terms of `death.hazard` are registered in `sim/deaths` with `source: 'sim/hunger'`, and allowance's `goodwill` term in `sim/exchange` with `source: 'sim/relations'`. They cannot move home today, because `contribute` needs the rule declared first and `sim/hunger` loads before `sim/deaths`.
Acceptance criteria:
- [ ] `contribute` accepts a contribution to a rule not yet declared; `seal` fails if any rule is still missing. A rule's spec may name its contributions' order (`order: [keys]`); without it they combine in the order registered. Both rules keep today's order, so floating-point results and the golden file hold.
- [ ] A lint in `npm test` holds each contribution's `source` to the module whose file registers it. The `hunger` and `frailty` terms move to `sim/hunger`; the `goodwill` term moves to `sim/relations`, or its `source` becomes `sim/exchange`: say which and why.
- [ ] A `product` rule's contributions declare tight ranges, checked as today in `explain`; a `sum` rule's range is optional, and allowance's three bounds of ±1e9 go (`ALLOWANCE_BOUND`, and `sim/hunger`'s import of `sim/relations` for it).
- [ ] `value` still allocates nothing (`tests/registry.js`); `node tests/perf.js --counter-cost` unchanged within noise.
- [ ] Refactor rules of `BACKLOG.md`: behaviour unchanged, `tests/golden.json` and `tests/counters.json` unchanged, `npm run verify` passes.
