# VB-443: Prototype demand-grown village shortest-path trees and exit landmarks
Status: done (2026-11-14)
Priority: 2
Size: M
Design ref: World and scale; Worn paths
Goal: Measure routing work avoided without forcing centre detours or changing production simulation.
Acceptance criteria:
- [x] Prototype one bounded resumable shortest-path tree per village, with endpoint-demand and observed-exit growth.
- [x] Keep arbitrary journeys exact: use the shared tree as a landmark, never force a trip through its root.
- [x] Test partial growth, closed house endpoints, physical budgets, disconnected land and cost invalidation.
- [x] Measure live cache misses, query expansions plus tree construction, invalidations, memory and timings on named scenarios.
- [x] Document the evidence and a deployment recommendation; leave production unchanged unless the prototype supports deployment.

Decision: research tooling only, owned by this experiment, outside saved simulation state and the production manifest.
Movement costs and ownership are read through existing modules. The simulation retains its native routes, so the experiment
cannot change the traffic that trains its trees. Cost is cache misses × A* work plus at most 64 tree expansions per demand,
with 2048 discovered records per village by default (one fully relaxed vertex may overshoot by at most six).

## Result and validation

Implemented tools/lib/village-trees.js and tools/village-tree-probe.js: one sparse bounded resumable tree per village,
endpoint-demand and actual-tread boundary-exit growth, exact clipped landmark heuristics, and certified root/ancestor subpaths.
Closed houses use all legal open neighbours; they never become transit nodes. Immediate selective invalidation protects
settled vertices and their incident edges. The native router still drives the simulation; research counters are separate.

48-day live runs: Tiny and Small seeds 7/42, Large seed 7 (809 living), and a Small seed-7 save after five years.
Additional Tiny 7/42 trials use smaller 8/256 limits. Every miss matched native preference, physical time and reachability.
Default demand A* expansions fell 19–26%; counting construction gave between 4.4% fewer and 15.4% more vertices.
Instrumented time was worse for both policies. Do not deploy this form. Incremental branch repair is the next candidate.
Details and raw results: docs/village-tree-study.md; docs/bench/village-trees.json.

The experiment found missing field/meadow development notifications, fixed separately as VB-444. No production tree/state
field, gameplay parameter or route representation was introduced. The prototype costs O(villages × capped tree records),
plus common bounded world-cost memo and reusable query buffers; all construction and tread hooks are measured.

Validation: tests/village-trees.js checks 144 exact queries, partial-potential consistency, multi-door houses, branch journeys,
distant cost decreases, touched increases/decreases, opening blocked neighbours, islands, caps, budgets and notifications.
npm test: 54/54 passed. Full final verification is recorded below after branch integration.

Final validation after merging bridge-construction main fcec025: npm run verify 108/108 passed (17 advisory targets out).
Rebuilt index.html. Current-main live smoke: 508 exact miss queries, no route/cost/time differences.
