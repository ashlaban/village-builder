# VB-230: The dependency check by layer, with a baseline that only falls
Status: done (2026-11-11)
Priority: 3
Size: S
Design ref: none (code structure). `docs/architecture/target-v2.md`, sections 3.1 and 3.2; VB-176.
Goal: VB-176's check enforces the load order: no lookup into a later module but `issue`. The target's rule is by layer (target-v2 3.1): calls go downward, reads are free, and influence goes upward only by a command, an event or a declared hook. Give each module its layer and report the calls that break the rule, against a baseline that only falls, so new code cannot add one.
Acceptance criteria:
- [x] Each module of `src/manifest.json` names its layer (kernel and world, material and land, social, agency, derived; composition roots apart: `sim/clock`, `sim/saves`, `sim/scenarios`, `sim`), in the manifest or its `@sys` line; a module without one fails `npm test`.
- [x] `tools/dependencies.js` reports every import and lookup from a lower layer to a higher one, by file and line, leaving out `issue`, rule contributions and, once VB-229 has landed, `emit`.
- [x] `tests/dependencies.js` holds the count to a baseline file that only falls (`--update` lowers it, as `tests/lint.js` does). The review of 9 November counted 29 of 250 with its own placement; record the placement used and the count found.
- [x] `docs/architecture/modules.md` gains the layer of each module; `ownership.md`, section 4, the upward calls by group.
- [x] No code under `src/` changes but the layer names; golden unchanged; `npm run verify`'s hard checks pass, its targets reported with their residuals.
