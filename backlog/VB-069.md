# VB-069: Golden mismatches show what changed
Status: done (2026-10-30, 347dc2c)
Priority: 1
Size: S
Arch: tooling
Phase: implement
Design ref: none (test infrastructure); REVIEW.md, Development, debugging and inspection.
Goal: `tests/golden.js` stores a hash per top-level key, so a mismatch says "`founders/7/year2`: pawns" and nothing more. Finding the change then means bisecting by hand.
Acceptance criteria:
- [x] `tests/golden.js --dump DIR` writes the canonical text of every hashed value, one file per entry and key (for example `DIR/founders-7-year2/pawns.txt`), with one line per leaf (`pawns[41].household = 7`), so two dumps compare with `diff`.
- [x] On a mismatch, the golden check re-runs the mismatching entries on the commit's `tests/golden.json` side, writes both dumps to `tests/out/` (git-ignored), and prints the first 10 differing lines per key, for example `pawns[41].household: 7 → 9`. The baseline side comes from `git stash` or `git worktree` of `HEAD`; document which.
- [x] `tests/golden.json` is unchanged; the hashes are computed exactly as today.
- [x] `.gitignore` lists `tests/out/`.
- [x] A test (not in the suites, run by hand and reported in the PR) changes one pawn's household in a copy of the state and shows the printed difference.
