# VB-170: The meeting's decisions and the debug actions as commands
Status: ready
Priority: 2
Size: M
Arch: core
Phase: implement
Design ref: Commands, time steps and views (Unified commands, Non-person entities: Decided); answer 4 to VB-076: the meeting issues `decide(custom, option)`; kill, retire and argue become debug commands.
Goal: A village meeting changes its practice by writing the settlement's customs directly (`Culture.meeting`, called from `holdMeetings` in `src/sim/lifecycle.js`), and the debug drawer acts through `Sim.killPawn`, `Sim.retireHolder`, `p.advocate` and the like. Make them commands, so every change of customs and every debug action has a source, a reason when refused, and a place where a player's command will join later. Depends on VB-167.
Acceptance criteria:
- [ ] A command's actor may be a settlement: `{ actor: { settlement: id }, verb: 'decide', args: { dim, option }, source: 'meeting' }`. `Culture.meeting` returns the changes it would make and `holdMeetings` issues one `decide` for each; the custom changes, is logged and recorded (`custom`) as today.
- [ ] Debug verbs with source `debug`: `kill` (cause `killed`), `retire` (a holder hands over), `argue` (a pawn takes up a cause: `args { dim, option }`), `rally` (a fifth of a village argues for an option), `skip` (advance the state by hours); the debug drawer issues them through `Sim.command`, and shows a refusal's reason.
- [ ] `tests/commands.js`: each verb, and its refusals (a dead pawn, a pawn holding no farm, an option out of range).
- [ ] Behaviour unchanged: `tests/golden.json` unchanged; `npm run verify` passes; the debug drawer works as before (browser smoke test).
