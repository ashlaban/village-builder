# VB-068: A command-line view of a run: `tools/sim.js`
Status: ready
Priority: 1
Size: M
Arch: tooling
Phase: implement
Design ref: none (development tooling); REVIEW.md, Development, debugging and inspection.
Goal: Each test prints its own report, and the only way to see a run is to write a script. One tool that seeds, advances and reports gives every task and every agent the same view of the simulation, and an answer to "what happened to household 12 in year 7".
Acceptance criteria:
- [ ] `node tools/sim.js --scenario founders|heirs|populous --seed N --map tiny|small|medium|large --years Y` seeds and runs, printing one line per year: population, births, deaths by cause, marriages, hungry household-days, mean grain, `st.demand` size and ms per game day.
- [ ] `--report households|pawns|jobs|customs|events|farms` prints that table at the end; `--pawn ID` and `--household ID` print one record in full, with its life events; `--at Y` stops at year Y.
- [ ] `--json` prints the chosen report as JSON instead (Maps and Sets as objects and arrays, typed arrays as arrays, functions left out), so its output can be piped to `jq` or read by a script.
- [ ] The map sizes match the generation screen's (VB-021); the tool uses `src/load.js` only and changes nothing in `src/`.
- [ ] `tests/tools.js` in `npm test` runs `tools/sim.js --scenario founders --seed 7 --map tiny --years 1` and `--json --report households`, and checks that the JSON parses and has one entry per household.
- [ ] CLAUDE.md lists the tool under Commands, with two examples.
