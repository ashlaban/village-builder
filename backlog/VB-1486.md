# VB-1486: Check: every theme defines every token
Status: ready
Priority: 2
Size: S
Design ref: Kim, 22 November; VB-1161
Goal: A theme that misses a token fails npm test.
Acceptance criteria:
- [x] A fast check (`tests/themes.js`, a line in `tests/suites.js`, fast tier) reads the stylesheet through `readSource` and the themes from `src/page/options.js`: every key of `THEMES` has a token block, every block's key is in `THEMES`, and every block sets every theme token of the list VB-1484 wrote.
- [x] A token used by the base (`var(--x)`) that no theme sets and the base does not define fails the check, named.
- [x] The check fails on a constructed stylesheet missing one token (the check's own self-test), and passes on the repository.
- [x] `npm test` stays within its ten seconds; `npm run verify` green. (themes.js takes 0.05 s; the suite's wall time on the shared machine, 13 s, is format.js's cold cache and the load, not this check.)

## Notes

Builds on VB-1484's token list.

Done (VB-1486). `tests/themes.js`: a theme's token block is a rule outside any @media with a selector part that is one compound carrying `[data-theme="x"]` (so `:root[...]`, `[...]` and `.theme-pv[...]` all count, whatever VB-1485 widens to); a block under @media is an override (Glass dark) and need not be complete, but its theme must be in THEMES. A rule like `:root[data-theme="mural"] .meter { --beads }` is scoped, not a token block, and counts as base.
Also checked: a custom property a theme block sets that is not in the list fails (keeps the list the one place a token is named).
Defined outside the stylesheet: `--x:` in inline styles and `setProperty('--x')` of `src/body.html` and `src/page/*` (`--on`, `--turn`, ...), so a var() the page sets does not fail.
The list holds 40 tokens (not 50); both themes set all of them; no gap found, `src/head.html` unchanged.
