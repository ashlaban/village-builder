# VB-1491: Map overlay: fertility
Status: done (2026-11-23)
Priority: 2
Size: S
Design ref: Farming (fertility of a field); page only.
Goal: Show how good each tile is as a field: `fertility(w, i)` of `sim/crops` on every `farmable` tile, in bands; land that cannot be farmed is left as it is. The key says what makes a tile better (its biome, a river beside it).
Acceptance criteria:
- [x] Tiles banded by `fertility` (the distinct values the map has, read from `sim/crops`, never copied); the key lists the bands present with their value and biome, and the river's share (`RIVER.irrigation`).
- [x] Registered with the registry of VB-1490 (one new file under `src/page/`, its line in `src/page.json`, an icon in `src/page/icons.js` in both icon sets, a key panel in `src/body.html`); no change to the switch itself. It gets the next free digit key.
- [x] Page script only: it reads `w` and `st` and writes neither; a sequential quantity uses one perceptually ordered ramp, readable in both themes over the map, and the key names the ends in the game's words and units.
- [x] Drawn again only when what it shows changed (as `page/ground` looks at most twice a second); a new world wipes it.
- [x] The browser check of VB-1490 covers it: on, off, no console error.
- 23 Nov 2026 (Kim, in session): the overlays and the switch were chosen from a mock; one overlay shows at a time.
- Decisions: the band's colour is its value's place on viridis between the poorest and the best fertility the rules allow (FERTILITY, RIVER), so a band keeps its colour across maps; reach already uses plasma, so the two read apart.
- The tiles' kinds (biome, river beside) are compared every 0.5 s while on, and the layer is drawn again only when one changed (the editor can repaint biomes); fertility itself is read from `sim/crops` per tile.
- The key reuses the reach key's one-column style (`reach-key` class), so `src/head.html` is unchanged; values given as the plan's tile line gives them (open meadow 100).
- `tests/smoke.js` counted the objects layer by index 13; a new overlay layer shifted it, so it now counts from the top (fifth from the end).
