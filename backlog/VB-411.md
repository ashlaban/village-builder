# VB-411: The lint asks for an open split task when a module passes 400 lines
Status: done (2026-11-13)
Priority: 2
Size: S
Arch: yardstick
Phase: implement
Design ref: none (code structure). backlog/VB-410.md
Goal: VB-410 made 400 lines a trigger in prose. The lint now checks it: a module over 400 lines needs an open task titled 'Refactor: ...' that names its key; with one it may grow. src/gen.js, over the line before the rule and with no split task wanted, is in the baseline at 545 lines, which only falls.
Acceptance criteria:
- [x] `tests/lint.js` fails a module over 400 lines that no open task splits, and its message says what to do (open the task, name it in the PR; no packing). With such a task it prints one line and passes.
- [x] The task is found by rule (`splitTask` in `tests/lint-rules.js`, cases in `tests/lintrules.js`): not done, titled "Refactor: ...", the module's key whole in the title.
- [x] `src/gen.js` is in `tests/lint-baseline.json` at 545 lines: it passes at or under that, and needs a split task to pass it.
- [x] `AGENTS.md`, `BACKLOG.md`, `docs/gates.md` and `docs/architecture/modules.md` say so.
Notes / questions:
- 13 Nov 2026, decided in the session with the user: enforce the split task mechanically; no split task for `src/gen.js`; 400 stays.
- Why 400 stays: it has no derivation, and any raw count is a judgement. What the number now costs is one filed task for a module, once, so it matters less than it did as a cap. At 400 the ten modules at the line each get a split task at their next growth, and those are the packed ones (VB-410's notes). The median module is about 150 lines. The number ends with VB-381.
- 13 Nov 2026, implemented and tried by hand: five lines added to `sim/heirs` (405) fail with the message; three added to `gen.js` (548) fail against its baseline; both restored. The lint reads `backlog/` only when a module is over the line.
- The weak point left: a split task that is opened and never taken. Its priority is the orchestrator's to set.
