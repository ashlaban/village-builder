# VB-668: Materials in the Stores tab: counts, all of them on request, and the meter against the work that asks
Status: ready
Priority: 2
Size: S
Design ref: docs/mocks/supply-scale.html; AGENTS.md, Deciding without Kim, 15
Goal: A material is held until a work asks for it, so the player is shown whether there is enough for what is planned, and can list everything held.
Acceptance criteria:
- [x] The Stores tab has three sections, each with one presentation (Kim: "a good start"): Supplies (VB-667; until it lands, today's stats stay there), Materials, Gear. A resource is sorted by what the player wants to know of it: how long it lasts (a supply), whether there is enough for what is planned (a material), what condition it is in (gear). The rule and where a new resource goes are written in `docs/architecture/modules.md`.
- [x] Materials (timber, stone, clay, bog ore, tar, wool, and what later slices add): a material is a count beside its icon. Where a work asks for it (the household's project plan: `sim/projects`, and what `Stores.reserved` holds back for it), a framed block names the work and its step, and shows each material it asks for on the one meter: what is held against what is asked, a mark at what is asked, "28 of 40".
- [x] By default the section lists the materials the household holds and those a work asks for; a switch, "All materials", lists every material's count, those of none too (Kim: "the materials view should have an option to view counts of all materials"). The switch is the page's own state and is kept as the selection changes.
- [x] Kinds within a material (the quern's rock today; stone and metals by kind when a slice gives a household more than one): the tile shows the total and the kinds under it, only where more than one is held. Where today's state holds one kind only, the criterion is met by the layout taking a list, shown in a test on a constructed list.
- [x] Gear (quern, cart, boat): as VB-664 shows them, moved under their own heading; nothing new but the section.
- [x] No strip of a chain of goods (sheaves to meals): tried in the mock and set aside by Kim.
- [x] Desktop. The page only reads `st` (lint); if a project's asked amounts need a read the `Sim` API lacks, it is added there with its test, and named in the notes. `node tests/smoke.js`, the `tests/browser*.js` touched; a screenshot under `docs/img/`. `node tools/same.js --base REF` prints `same`.

Implementation notes (VB-668):
- `src/page/cards.js`: Stores tab = Supplies (today's stats, peat with them), Materials (`MATERIALS`, `materialsOf`, `worksOf`, `materialsHTML`), Gear, Health. `src/head.html`: the frame, kinds line and switch styles. The "All materials" switch is `allMaterials`, the page's own variable, so it is kept as the selection changes. No `Sim` API added: the asked amounts are `plan.reserved[good]` where `plan.reasons[good] === 'build'`, read through `VB['sim/projects'].projectsOf`.
- Decisions: timber is the household's woodpile (`hh.wood`, the one pile the firewood stat also shows; a project's `wood` is asked of it), so the Timber tile and the Firewood supply count the same loads. Peat stays among the supplies (it burns). Clay, bog ore and wool are held by no project's step today, so they only show as counts. A work's name is its plan's `what` (New field, A boat ...), its step the open step's kind name. The meter's max is 1.25 times what is asked, the mark at what is asked.
- Test: `tests/page.js` checks the three sections, the switch (6 materials listed) and, through a hook patched into the page, the layout on a constructed list (kinds only where more than one; a work's "6 of 10" and its mark).
