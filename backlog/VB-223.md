# VB-223: Fixtures as release assets, remade by a nightly workflow
Status: ready
Priority: 1
Size: M
Arch: yardstick
Phase: implement
Design ref: none (tooling). Kim's answers of 8 November 2026 (`QUESTION_ARCHIVE.md`, "VB-202"): the fixtures stored as release assets, not in Git LFS or the orphan branch; remade by a nightly GitHub workflow; no `medium-y60`. `docs/roadmap.md`, section 6 (late fixtures); VB-193.
Goal: Keep the late fixtures current without anyone remembering to. Nothing remade them from 5 to 8 November: `npm run nightly` remakes stale fixtures, but the scheduled nightly task has been disabled since 2 November, and the sessions that changed the golden file never ran it (VB-202's notes). Kim, 8 November: a GitHub workflow remakes them each night, and they are stored without keeping old versions. Today each publish force-pushes about 40 to 60 MB to the orphan `fixtures` branch, whose old objects may linger in the repository; Git LFS would keep every version against the free 10 GiB until the repository is deleted. The assets of one release are replaced in place, the old ones deleted, with no total size or bandwidth limit, and anyone fetches them over HTTPS without logging in (tested from a cloud session on 8 November).
Acceptance criteria:
- [ ] `node tools/fixtures.js publish` uploads the four saves and their stamps as the assets of one release, tagged `fixtures` (made if absent, marked a pre-release so it is never the latest), replacing each asset in place; it refuses, as today, unless every fixture is fresh and undamaged, and needs a token (`GH_TOKEN`), so in a session without one it says so and publishes nothing.
- [ ] `node tools/fixtures.js fetch` (and `loadFixture`'s first fetch) downloads them from `https://github.com/ashlaban/village-builder/releases/download/fixtures/<name>.gz` and `.json`, without a token; it checks the whole set before replacing any local save, and keeps the local saves when offline, as today.
- [ ] `.github/workflows/fixtures.yml` on `main`, nightly at a fixed hour (UTC) and by hand (`workflow_dispatch`): `npm ci`, fetch, remake the stale fixtures, publish only if one was remade. Permissions `contents: write` only; one run at a time (`concurrency`); a timeout of 90 minutes. It runs no bench, since the bench times its machine.
- [ ] `tests/fixture-tools.js` exercises publish and fetch against a local stand-in for the release (no network, no token), with today's checks: stale, damaged and partial sets refused, offline fetch keeps local saves, two publishers do not leave a mixed set.
- [ ] The orphan `fixtures` branch retired: no tool reads or writes it; Kim deletes it (the PR says how: `git push origin --delete fixtures`). `npm run nightly` fetches and benches, and remakes locally only what is still stale; `docs/agents/worker.md`'s wrap-up says so.
- [ ] `AGENTS.md` (Commands, Fixtures) says the workflow remakes and publishes the fixtures each night, and that a PR changing the golden file need not remake them.
- [ ] After merging, the workflow run once by hand on `main`; the run's link, its minutes and the release's asset sizes in the notes.
Cost: about 20 minutes of a standard GitHub runner on a night after the golden file or the save format changed, a minute otherwise (public repository: no minutes charged); 15 to 25 MB of release assets, replaced in place.
