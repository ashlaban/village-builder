# VB-413: Module length: 400 lines is a trigger for a split task, not a cap
Status: done (2026-11-13)
Priority: 2
Size: S
Arch: yardstick
Phase: implement
Design ref: none (code structure). backlog/VB-055.md (why not a cap on length); backlog/VB-381.md (the measures that replace it)
Goal: The cap of 400 lines a module packs the modules that reach it: lines grow dense, and code goes where there is room, not where its concern lives (the numbers are in the notes). Until VB-380 and VB-381 replace it, `tests/lint.js` reports a module over 400 lines and does not fail; the task that takes a module over the line opens a task to split it by concern and names it in its PR. No hard limit on length.
Acceptance criteria:
- [x] `tests/lint.js` fails no module for its length; it prints one line for each module over 400 lines (its length and that it needs an open split task). The column limit and its falling baseline stay as they are.
- [x] `tests/lint-baseline.json` holds only what the lint still reads (the long lines of each file).
- [x] `AGENTS.md` (Conventions), `BACKLOG.md`'s refactor rules, `docs/gates.md` (row 3) and `docs/architecture/modules.md` (Adding things) say the same: 400 lines is a trigger; the task that crosses it opens a split task ("Refactor:", checked with `tools/same.js`) and does not pack lines or move code to make room.
- [x] VB-380 and VB-381 get a note: the length cap is already gone; their own criteria are unchanged.
Notes / questions:
- 13 Nov 2026, decided in the session with the user: the interim change now, not after the move to TypeScript; no hard limit on length, as Kim's decision of 10 November reads (`backlog/VB-055.md`).
- What the cap did, measured on 13 November (`wc -l`, 107 source files): 10 files within 10 lines of 400 (`culture`, `sim/heirs`, `sim/relations`, `sim/stores` at 400; `sim/plans`, `sim/records` 399; `sim/kinds` 398; `sim/commands` 396; `sim/lifecycle`, `sim/rules` 390). In those, 5 to 10% of lines hold three or more statements and up to 15% are 140 columns or wider; VB-380 measured `sim/relations` at 691 lines formatted. Placement by room: VB-359 and VB-328 (`sim/kinds` full), VB-123 (`sim/plans`), VB-175 (`sim/heirs`).
- Why 400 stays as the trigger: the number has no derivation (VB-013 set it as a convention), and raw lines measure little before a formatter. It is kept because it is the line every module was held to, so crossing it marks exactly the modules the cap was packing; VB-381's exports and function length are the measures meant to last.
- Why no hard backstop further out: it is the same wall later, with the same cheap ways past it.
- 13 Nov 2026, implemented. `tests/lint.js`: `MAX_LINES` became `SPLIT_LINES`, a note and no error; the baseline's `lines` went, and `--update` writes only files that have long lines (none today, so the file is `{}`). The lint on this tree prints one line, `src/gen.js: 545 lines, over 400`, and `lint ok`. No source under `src/` changed, so `index.html` is as it was.
- Left open: `src/gen.js` (545 lines) has no split task; it was over the line before this rule. The ten modules at the line are not unpacked here: each is split when a task next takes it over.
