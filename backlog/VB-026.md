# VB-026: Name generators, and farm names in big villages
Status: done (2026-11-01)
Priority: 3
Size: M
Arch: expansion
Phase: implement
Design ref: Naming of farms. Not checked tonight.
Goal: Villages of 12-16 farms run out of direction names. VB-021 numbers the extra ones ("Östergården 2"), which is a placeholder. Villages are also named from 88 syllable pairs; a unique name is forced within a map.
Acceptance criteria:
- [x] A module `src/sim/names.js` (`VB['sim/names']`, `@sys` header, in `src/manifest.json` before `sim/layout`) holds name generators grouped by the kind of thing named: `farm`, `village`, `culture`. Each generator is a function `(ctx, rand) => name | null` (null when it has nothing to offer); `ctx` holds the world, the entity and the names already taken.
- [x] Farm generators: `compass` (today's direction names, Mellangården included), `landmark` (from the surroundings, as lone farms get today: Strand, Lunden, Backa, Myra, Ängen and the like, extended with more landmark words), `owner` (from the first holder's given name, e.g. "Olofsgården", in the genitive as `patronym` builds it). Village generators: today's syllable names. Culture generators: today's `nameCulture`.
- [x] A culture holds a preference: an ordered list of generators per kind (`c.namePrefs`, `@state` documented). For now every culture has the same list: farms `compass`, then `landmark`, then `owner`; the first generator that gives a name not already taken in the village wins. A number is added only if all fail.
- [x] `nameFarms` and the naming of new farmsteads (VB-032) go through the culture's preference; existing names at seeding stay the same where today's rule gives a unique name, so small villages keep their names.
- [x] A test: a village of 16 farms has 16 distinct names and no numbers at seeds 7 and 42 (populous medium); an `owner` name follows the holder's given name.
- [x] Re-record the golden file (names in big villages change) and list the changed entries in the PR.
Notes / questions:
- Kim, 2026-10-30: the name generation system has many generators for the different entities; in the long run, cultures prefer different kinds of generators (so names drift and split with cultures). For now, landmarks and owner names are two generators that combine with the existing compass-direction generator.
- Later: cultures that split off (fission) may get a changed preference; people's given names could use the same system.
- Kim, 2026-11-01 (stability review, `docs/review-stability.md`): fix naming so that few names repeat on the map. Chosen: this task, plus one label per village of two or more farms, a founded village's farm named for its founder, and lone-farm names unique on the island.
- 2026-11-01: built. `src/sim/names.js` holds the generators (`compass`, `landmark`, `owner` for farms; `villageName` and `founderName` for villages). `landmark` offers the old lone-farm word first, then other words for the same ground (Viken, Näset; Åsen, Kullen; Mossen, Kärret; Gärdet, Vreten...) and prefixed compounds (Björklunden, Sandstrand, Långmyra), in an order fixed by the house tile: 60 to 130 names a farm. Culture names (`nameCulture`) stay in `sim/society`, as they are made from a settlement's name.
- The preference lives on each culture as `c.namePrefs` (`NAME_PREFS` in `src/culture.js`, which loads before the sim modules); a split copies its parent's.
- Beyond the criteria: a lone farm's village takes its farm's name, unique among the island's villages, so that the label is unique (the design's "its map label shows the farm name only" still holds); a farm in a village founded in play bears the village's name (Erikstorp); the page labels any village of two or more farms once, by its name, where it labelled each farm of a village without a green ("Nybygget", "Nybygget 2" ... in every hamlet). `design.md` may want a line for the hamlet label.
- Farms named in play draw from a stream seeded by the house tile (`tileRand`), not `st.rand`, so a name never shifts the simulation's history. The golden file changed only in names, event texts that name farms and villages, and the new `namePrefs` (and the `Culture` API's `NAME_PREFS`).
- Measured in `docs/review-stability.md`: repeated map labels after 60–80 years fall from 32–94 per run to 0.
