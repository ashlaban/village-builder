# VB-1135: Fix: a refusal in the step that stopped a skip is not told by the next
Status: done (2026-11-19)
Priority: 3
Size: S
Arch: life
Phase: implement
Design ref: The player and what they see (Skip to the next event)
Goal: No refused command of the played pawn passes a skip unread.
Acceptance criteria:
- [x] A command of the played pawn refused in the same step as another stop of a skip (an event, hunger, an offer) stops the next skip begun before the game runs on, once (`skipStop`, `src/sim/notable.js`: the cursor's `t` is moved to the new skip's start by `skipFrom(st, last)`, so `pl.refused.t > from.t` no longer holds).
- [x] A command refused while the game stands between two skips, which the page already showed the player, does not stop the next skip.
- [x] A check on a small constructed state in `tests/skip.js`: a refusal and a death in the household in one step stop two skips; `skipStop` still writes nothing to `st`.

Noted by VB-1108, 18 November 2026.

Decisions: the cursor keeps the refusal last judged (`ref`, told or passed) and the one seen at the last ask (`seen`), as plain data `{verb, why, t}`; a refusal stops a skip when it is not `ref`, once. A skip that goes on (`skipFrom(st, last)`) keeps `last.ref` when the refusal is still the one seen at the last ask (the stopping step's, untold), and passes it when it changed while the game stood. A cursor of before this takes its `ref` by the old rule (`t <= from.t`). Compared by value, not identity, since a load makes new objects.
