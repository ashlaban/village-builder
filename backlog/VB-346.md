## Implementation notes
- `CROPS` is a plain constant in `src/sim/rules.js` (after `ECON`), not a registry rule: nothing changes a row at run time yet, so there are no
  contributions to combine and it needs no seal; it never enters `st`. Row `barley`: `yield` 100, `seed` 25, `sow` [0, 0, 9] (season, first, last
  day), `ripe` 26, `wear` 0.08, `frost` [2, SEASON_DAYS - 1], `hours` {plow 20, sow 2, weed 2, reap 5, thresh 6}. `ECON.fieldYield`, `seedPerField`,
  `sowWindow`, `ripeAfterDays` and `SOIL.wear` are gone (moved, not copied); `tests/` and `tools/balance.js` read the row.
- `fd.crop` is set at all three places a field is made (`finishBreak`, two in `layout.js`); `saves.js` gives an older save's fields `barley`.
  `sim/fields` (yield, ripening, soil wear, the frost day, per field), `sim/kinds` (sowing window, seed) read the field's row.
- Where the hours live now: `CROPS.barley.hours` in `src/sim/rules.js`; `KINDS.plow/sow/weed/reap/thresh.hours` take them from it (VB-333 and
  VB-334 change the row, not the kinds). They are read by crop only once a second crop exists (a job's `hours` can carry the field's then).
- Seed targets (`sim/plans`, `sim/hunger`, `settle`, `farmclaims`, scenarios) and plans' `closing` window read `CROPS.barley` directly: they have
  no field in hand; they follow when the head chooses the crop.
- The frost check now walks the fields each day (it was a date guard first); a field loop already run daily beside it.
