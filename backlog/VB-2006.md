# VB-2006: Tests run by no tier: give each its @suite line or remove it
Status: ready
Priority: 2
Size: S
Design ref: docs/testing.md; tests/lib/tiers.js
Touches: tests/dress.js; tests/gathertie.js; tests/harvest.js; tests/sites.js; tests/calibrate.js; tests/runner.js
Goal: Every test in tests/ runs in a tier, or is named as not a test
Acceptance criteria:
- [ ] Each of `tests/dress.js`, `tests/gathertie.js`, `tests/harvest.js`, `tests/sites.js` and `tests/calibrate.js`, which no tier runs (none has a `// @suite` line, nor had a line in `tests/suites.js` before VB-1933), is run once by hand; the result is recorded in this file.
- [ ] Each one that passes and protects a rule gets its `// @suite` line (fast or integration if it takes under 5 seconds, else extended); one that fails gets a repair task or is mended here if the fix is small; one that only duplicates another test, or is a tool rather than a test (`calibrate.js`), is deleted or moved under `tools/`, with the reason given.
- [ ] `tests/runner.js` asserts that every `tests/*.js` either has a `// @suite` line or is on a short named list of files that are not tests (`run.js`, `suites.js`, `lint-rules.js`, `backlog-page.js`), so no test is left out of every tier by accident again.
- [ ] `npm run verify` passes.

Noted by VB-1933, 28 November 2026.
