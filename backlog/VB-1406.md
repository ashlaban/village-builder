# VB-1406: Refactor: declare beside the owner: the lists every task appends to become registries joined at load
Status: ready
Priority: 1
Size: L
Design ref: none (code structure). docs/architecture/target-v2.md, section 2 (principles 2 and 18) and 11.2; docs/architecture/modules.md, Adding things; backlog/VB-418.md, backlog/VB-228.md (the pattern); backlog/VB-419.md, VB-417, VB-455 (the splits it touches)
Goal: Over PRs #149 to #198 (16 to 21 November), 14 of the 19 files touched by the most tasks are hot because every feature appends a line to a list in them, not because two concerns share the file (`docs/plans/VB-1406-overlap.md`: the counts, the method and its limits). Splitting by size moves such a list and leaves it hot; the one split that lowered overlap, VB-418, replaced a list with a registry. Make that the rule everywhere: the module that owns a thing declares it beside the code, and a thin registry or a tool joins the declarations in a fixed order. This task writes the rule into the architecture, lands the steps that only tooling reads, and opens one task a step for the rest, in the order below. Behaviour does not change: each step shows `same`.
Acceptance criteria:
- [ ] The rule is in the architecture before code moves: `docs/architecture/target-v2.md` gains it in section 2 (proposed as a clause of principle 18, or a principle of its own: "what a feature adds to a shared list is declared by its owner; the list is joined at load or by a tool, in a declared order, never by load order") and a note in 11.2 naming this task; `docs/architecture/modules.md`, Adding things, says for each kind of thing (a module, a state field, a test, a counter, a tunable, a migration, an event kind, a `Sim` name) where its one declaration goes; `AGENTS.md` (Finding things, Conventions) names the greps in place of the files. `design.md` is not changed: no Decided mechanism moves (searched for the rules file, tunables, the facade, the manifest and migrations; say so again if the search finds one).

- [ ] Step 2, counters: a module declares its work counter at load beside the loop it counts (`src/vb.js` 12 tasks to 0); `tests/counters.js` reads the joined list as it reads `VB.COUNTERS` today. `tests/counters.json` is a recorded baseline and stays: the task proposes recording it at merge or at night, not in each task, as a question for Kim.

- [ ] Step 8, event kinds: one record a kind, declared by the module that emits it: how long it is kept (`HISTORY`), its chronicle group, whether it is personal, whether it stops a skip, its icon and word on the page. `sim/notable` is split into the skip and the chronicle, which share only the record (16 to 8 and 6); `sim/records` 10 to 6.
