# VB-073: Simulation state as plain data, without closures
Status: ready
Priority: 2
Size: M
Arch: core
Phase: implement
Design ref: none (saves); REVIEW.md, Development, debugging and inspection.
Goal: `st` holds functions: `st.countDemand`, and on `st.cenv` `byId`, `settlementOf`, `voiceOf`, `nameCulture` and `onSplit`, and `members()` on each settlement. A state with closures cannot be saved (VB-074), and closures over `st` hide what a function depends on. Depends on VB-072 (which removes `st.rand`); if it is not done, mark this blocked.
Acceptance criteria:
- [ ] `st.countDemand()` becomes `countDemand(st)` in `src/sim/heirs.js`, exported in `Sim` as `Sim.countDemand`; callers change.
- [ ] `Culture` functions take the environment's lookups as an argument (`hooks`: `byId`, `settlementOf`, `voiceOf`, `membersOf`, `nameCulture`, `onSplit`), built once in `src/sim/society.js` from `st`; nothing on `st.cenv` or its settlements is a function. `calibrate.js` builds its own hooks.
- [ ] A test walks `st` (except `st.w`) and fails on any function value, after seeding each scenario and after 1 year.
- [ ] Behaviour unchanged: `npm run verify` passes; in `tests/golden.json` only `cenv` entries (whose nested functions hashed as `fn`) and the `Sim` and `Culture` API-key hashes may change; list them in the PR.
