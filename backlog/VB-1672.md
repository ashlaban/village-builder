# VB-1672: Side by side: choose parallel tasks from their footprints and the branches in flight
Status: blocked
Waits for: VB-1671
Priority: 2
Size: M
Design ref: docs/plans/VB-1671-conflicts.md; docs/agents/worker.md, section 1
Goal: The orchestrator and a session starting a task choose work that edits different functions from the work in flight, by a tool, not by judgement; each merge reports how far the declared footprint matched
Acceptance criteria:
- [ ] `node tools/lanes.js [N]` picks, from the ready tasks in `backlog.js next` order, up to N that touch no function or table in common with each other or with the work in flight; a plan or a wrap-up runs alone; a task with no `Touches:` line or `Touches: unknown` falls back to the rule of `docs/agents/worker.md` (different archs) and is listed as such. For each task held back it prints what it meets and where (`VB-1234 sim/jobs (allot)`).
- [ ] The work in flight is (a) the run's inbox claims, and (b) the branches pushed to origin and not merged into main (`claude/*`, the last few days): their edits since their merge base with main, by enclosing symbol, from one symbol finder in `tools/lib/` (the heuristic of `docs/plans/VB-1671-replay.js`). Half the conflicted merges since 15 Nov were between sessions, not within a run (`docs/plans/VB-1671-conflicts.md`).
- [ ] `node tools/lanes.js --check VB-NNN`: what in flight a task would meet, for a session that starts one by hand. `inbox.js claim` takes functions (`sim/jobs:allot`) beside files and reports a clash at function level.
- [ ] The list and bookkeeping files are left out through one declared list in the tool, its comment naming VB-1406.
- [ ] Measured after each merge: `node tools/lanes.js --measure VB-NNN BASE..TIP` compares the declared `Touches:` with the edits, by symbol (recall, precision), into the inbox result; the night's PR gives the totals. `docs/agents/worker.md`, section 1, step 1 uses the tool.
- [ ] `tests/lanes.js` on a constructed backlog and a scratch git repository; a row in `docs/agents/changes.md`; `npm test` and `npm run verify` pass.
