# VB-1490: Refactor: world/: the terrain's codes, names and grid apart from its generator
Status: ready
Priority: 2
Size: M
Design ref: `docs/architecture/target-v2.md` 3.1 (the layers; Player and presentation); `docs/architecture/modules.md`
Goal: `src/gen/` holds the terrain's generation, its representation and its presentation (review of 23 November). First of four steps: the representation gets a home of its own, `world/`, which the generator, the simulation and the drawing all read, so that about 30 sim modules no longer import the `gen` facade (which carries the bake) for `B` alone.
Acceptance criteria:
- [x] New modules, each with its `@sys`, listed in `src/manifest.json` before all that read them, layer kernel: `world/grid` (`NX`, `NY`, the odd-r directions, `toAxial`, `hexDist`, `hexLocator`, and `csample(w, arr, x, y)` as a function of the module), `world/biomes` (`B`, and the biomes' `key`, `name` and `water`), `world/geology` (`ROCK`, `ROCKS`, `DEPOSIT`, `DEPOSITS`, `ENDLESS`, `FIND`), and `treeStage` in a world module (it is the contract between `sim/forest`, `sim/spread` and the drawing). The split may differ where the code asks for it: say why in the notes.
- [x] What stays in `gen/` for now: `COVER`, `fullTrees`, `meadowStones`, `cover.set`, `keep`, `restore`, `setDeposit`, `reveins` (generator rules applied by hand), and `setBiome` with the pigments (`c`, `c2`, `shade`), until VB-1493 takes the colours out.
- [x] No sim module reads `VB['gen']` for `B`, `treeStage` or a code of the ground: they read `world/*`. The page and the tests read the names and codes from `world/*` too. `gen/cover`, `gen/rivers` and `gen/geology` import what they were handed as `K`, `G` or `B` only because `gen` loaded after them.
- [x] `w.csample` is gone from `w` (the one function in it); `tests/plaindata.js` no longer exempts `w` on its account, if it did.
- [x] A river's kind by flow, a commit of its own and the one change of behaviour (Kim, 23 November): `kind(w, i)` in a world module names Brook, Stream or River by `w.river[i]` (below 38 a brook, below 225 a stream: today's widths 8 and 16 at the default hex size), not by the drawn width; `page/tileinfo` reads it there. At R = 28 the names are as before: a check shows it on a generated island.
- [x] Moves and renames in separate commits (Refactor rules). `node tools/same.js --base REF` prints `same` (functions are not compared); the pixel check of VB-1489 prints `same`; `npm run verify` and `node tests/smoke.js` pass.
- [x] `docs/architecture/modules.md`, `tools/writes.js` (`GEN`), the `@state` lines and `AGENTS.md` (Finding things, Conventions) follow where they name what moved.
