# VB-1490: Page: a tile turned to meadow recolours the overview without waiting for a tree change
Status: ready
Priority: 3
Size: S
Design ref: src/page/animate.js; src/page/chunks.js
Goal: A tile whose biome changed is repainted in the frame the page sees it, whether or not a tree stage changed in the same step.
Acceptance criteria:
- [ ] `updateSettlement` (`src/page/animate.js`) repaints when `st.biomeDirty` has tiles, not only when `st.treeDirty` has: a step that sets only `st.biomeDirty` recolours the overview in the next frame, and the set is cleared.
- [ ] A check in `tests/page.js`: a tile added to `st.biomeDirty` alone is gone from the set after a frame, and its overview chunk's texture was updated.
- [ ] `npm test` and `npm run verify` pass.

Notes:
- Found while diagnosing the flicker of VB-1489 (23 November). Measured headless, populous, small map, seed 123, two years: 487 steps set `st.biomeDirty` against 56 that set `st.treeDirty`, so most biome changes wait, up to a game day, for the next tree change.
- Raises how often the overview is repainted, and that repaint is whole and unbudgeted (VB-1491): take VB-1491 first, or measure the frame cost on a late save here (docs/cost.md). Both edit `src/page/chunks.js`: one at a time.
