# VB-239: Saves: derived state by one rule, no empty movements, old formats refused
Status: ready
Priority: 3
Size: M
Design ref: none (code structure). `AGENTS.md`, Conventions (`st` is plain data).
Goal: Three things in and around `src/sim/saves.js` are more than they need to be. Derived state is kept out of a save in three ways: hidden as a non-enumerable property (`st.idx`, `st.awake`), saved (`st.jobsBy`), or rebuilt on load (`st.living`, `st.liveHouseholds`). `Stores.take` records a movement of nothing, which is the codec's only `-0`. And `load` migrates format-1 saves from before VB-099, VB-127, VB-159, VB-169, VB-198 and VB-204, though the only saves kept are the fixtures, remade nightly (Kim, 10 Nov 2026).
Acceptance criteria:
- [ ] One rule for derived state: `sim/saves` holds a list `DERIVED` of the fields of `st` that are not saved, each with the function that rebuilds it on load (`living` and `liveHouseholds`: `rebuildLiving`; `idx`: `index`; `awake`: null, rebuilt at the next step; `jobsBy`: from `st.jobs`). `save` skips them and `load` rebuilds them. `st.idx` and `st.awake` become ordinary properties: no `Object.defineProperty` is left in `src/`. Their `@state` lines say "derived, not saved (`sim/saves` DERIVED)".
- [ ] Stays saved, and the task says why in a comment at `DERIVED`: `st.idlers` (who is in it depends on when in the hour it was made, VB-074) and `st.pathCache` (a route searched again after a load may differ from the one cached, so a loaded run would leave the saved one).
- [ ] `tests/saves.js` holds, as today, that a run saved and loaded mid-year goes on to the same state as the run that was not; `tests/plaindata.js` and the invariants check the derived fields against their sources.
- [ ] `Stores.take` returns 0 without recording when nothing was taken, and `put`, `move` and `cook` likewise for nothing; no ledger entry or yearly total has `n` of 0. Invariant in `tests/lib/invariants.js`. The codec keeps `-0` (it is two lines, and the state may hold one again).
- [ ] `FORMAT` is 2. `load` refuses any other format with today's message, and the migrations go: `contacts`, `events`, a village without `ledger`, holders without `totals`, dissolved households' ledgers, `haySpoilt`, `player`, `migrateTies` (and its export from `sim/relations`), and `trimRoutes` on load if VB-236 has landed. `node tools/fixtures.js make` remakes the fixtures locally for the task's own checks; the nightly workflow publishes them.
- [ ] `tests/golden.json` is re-recorded only if the canonical hash changes (the empty movements, and `jobsBy` if it leaves `st`'s keys), and the PR lists the changed entries; no number of the simulation changes: living, households and grain at populous and founders, small map, seeds 3, 7, 11, 42, 15 years, the same before and after.
- [ ] Save and load at `medium-ref` (`node tools/bench.js`) no slower than before; the PR says what fell (lines, the save's size).
- [ ] `npm run verify` passes.
