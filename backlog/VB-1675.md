# VB-1675: Review: hard checks assert what holds in any state, not a seeded run's outcome
Status: ready
Priority: 3
Size: M
Design ref: docs/review-principles-2026-11-24/synthesis.md (Invariant catalogue, S2); docs/testing.md; tests/lib/bands.js; tests/hay.js, tests/meadows.js, tests/byre.js, tests/head.js; docs/architecture/target-v2.md, principle 17
Goal: A test in the fast or verify tier fails only on a rule broken in any state, so a new mechanism that moves a seeded run (VB-1553) is not held back by a count, share or rate asserted on that run.
Acceptance criteria:
- [ ] Every assertion of a share, rate or count on a seeded run in the fast and verify tiers is listed in the PR, starting with `tests/hay.js`, `tests/meadows.js`, `tests/byre.js` and `tests/head.js`.
- [ ] Each is moved to a band (`tests/lib/bands.js`) or rebuilt on a constructed state that states the rule it checks; none is deleted without a line saying why.
- [ ] A lint finds a literal list in `tests/` equal to a registry's keys (verbs, kinds, goods), and the lists it finds read the registry instead.
