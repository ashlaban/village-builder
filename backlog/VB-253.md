# VB-253: The player as head: every choice of the plan as a command
Status: blocked
Waits for: VB-252, VB-123
Priority: 2
Size: M
Arch: year
Phase: implement
Design ref: Work: opportunities, plans and tasks (design.md, section 7); docs/review-work.md; design.md section 15 (Parity of command)
Goal: Parity of command (design.md, section 15): every act a pawn may take is the player's to command. A head's acts are the choices of its plan. Give each a verb, which the holder's own rule and the player both go through.
Acceptance criteria:
- [ ] Verbs in `src/sim/commands.js`, each checking the act is possible and returning why not: set a target of the plan (within bounds the verb states: hay 0 to 3 winters, fields 0 to what the hands can work, the woodpile 0 to twice the winter goal); choose the tile of the next field or meadow (claims, reach, the farm's block: the checks of `chooseTile` and `chooseMeadow`, moved into the verb); set the order of the season's routines; choose or drop the project (VB-255's menu; until it lands, the land step only).
- [ ] The holder's own rule issues the same verbs with `source: 'pawn'`; the player's go before it, and where the player has made no choice the holder's rule runs, as for any pawn (`tests/commands.js`: only the verbs call the acts they wrap).
- [ ] Only the holder may issue them: a player in a pawn that is not the head is refused with the reason. A choice lasts until the season's plan is remade (order), the tile is used (tile) or the player clears it (targets, the project).
- [ ] With no player commands the run is unchanged: `tests/golden.json` unchanged. A test plays a head at seed 7: a tile is chosen and the field is made there; a refused tile (claimed, out of reach) returns its reason; a raised hay target is met by the next winter.
- [ ] `Sim` API entries for the page (VB-256). `npm run verify` passes.
Cost: none in a run without a player.
