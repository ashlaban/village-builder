# VB-074: Save and restore the simulation state
Status: ready
Priority: 2
Size: M
Arch: core
Phase: implement
Design ref: Pace (a run lasts 40–80 hours); Systems overview (Save and load: missing).
Goal: A run cannot be saved. A save is needed to play for 40 hours, and it is the best debugging tool there is: a bug report carries the run, and a test can start from it. This task makes saving and loading work in Node; the page's buttons and autosave follow from the plan (VB-077). Depends on VB-072 and VB-073; if either is not done, mark this blocked.
Acceptance criteria:
- [ ] `Sim.save(st)` returns a JSON-compatible object: `format` (1), the scenario, seed and map size, and the whole state. Object references become ids: an agent's job and a job's field, farm and stretch by key and index. Maps, Sets and typed arrays are encoded so that they come back as the same types.
- [ ] The tiles the simulation changes are saved (at least `w.trees`, `w.treesMax`, `w.stones`, `w.biome`, `w.dev`; grep for writes to `w.` in `src/sim`), and `Sim.load(w, data)` takes a world freshly generated from the saved seed and size, applies them, and returns a state.
- [ ] `tests/saves.js` in `npm run verify`: founders and heirs at seeds 7 and 42 are saved after 2 years, written as JSON text, parsed, loaded into a new world and advanced 1 year. The hashes of `tests/golden.js` (`hashKeys`) then equal those of the run that was never saved. The same for populous tiny at seed 7, saved after 1 year.
- [ ] The PR reports the save size, as JSON text and gzipped, for populous medium after 2 years and founders after 50.
- [ ] `tools/sim.js` (VB-068), if done, gains `--save FILE` and `--load FILE`.
