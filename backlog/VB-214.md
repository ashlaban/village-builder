# VB-214: Saves in the page, named by their build
Status: ready
Priority: 2
Size: M
Arch: life
Phase: implement
Design ref: Commands, time steps and views (Saving: Agreed 30 Oct, revised 7 and 8 Nov by Kim); `QUESTION_ARCHIVE.md`, "VB-077" (30 Oct) and "VB-079" (questions 3 and 8); `docs/review-life.md`, section 5.
Goal: VB-074 saves a run in Node; a player cannot yet keep a game. Save and load in the page: to and from a file, and in the browser keeping the last 3, by hand and when the page is hidden. Each save names the build that made it, and a save from any other build is refused with a message and an easy way to delete it and start a new game (Kim, 30 Oct and 8 Nov). Autosave at the moving round waits for a save under 0.5 s (VB-215).
Acceptance criteria:
- [ ] `build.py` writes a build id into the page: a short hash of the sources it inlines, the same for the same sources, so `python3 build.py --check` still holds.
- [ ] A page module (`src/page/saves.js`, in `src/page.json`) saves `{build, savedAt, label, save: Sim.save(st)}` gzipped (`CompressionStream`):
  - **Save** in the menu, and on `visibilitychange` to hidden, into IndexedDB, keeping the last 3;
  - **Save to file** downloads it as `.json.gz`;
  - **Load file** reads `.json.gz` or `.json`.

  The label names the scenario, seed, map, year and season, and the played pawn if any (VB-169).
- [ ] The generation screen lists the stored saves (label, when saved) with **Continue** and **Delete**. A save of another build shows "Made by another build of the game; it cannot be loaded", with **Delete it** and **Start a new game**. The same holds for a file. The check is the page's: `Sim.load` keeps its format rule, so fixtures still load across builds.
- [ ] A page save's file loads in `node tools/sim.js --load FILE` (the wrapper is unwrapped there), so a bug report can carry a played run.
- [ ] Load regenerates the world from the save's seed and size, then loads the state: the run goes on as in Node, `st.player` included.
- [ ] `tests/browser*.js` (real Chromium):
  - save, reload the page, continue, and the year and the played pawn match;
  - a save with another build id is refused with the message, and **Delete it** removes it;
  - a file saved and loaded again matches the state's hash;
  - no console errors.
- [ ] Times reported, in Chromium and in Node (`tools/bench.js`), at small-y40 and medium-y5, each stage apart (encode, stringify, gzip, IndexedDB write; read, gunzip, parse, decode). Stale fixtures are said to be so. On 5 November, in Node: 1.09 s to save and 0.32 s to load at medium-y5. The 0.5 s line is VB-199's and VB-204's, not this task's.
- [ ] Screenshots of the menu and of the generation screen's saves, before and after (desktop and phone), in `docs/img/vb-214-*.png`. Golden file unchanged.
