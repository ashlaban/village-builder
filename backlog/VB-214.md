Goal: VB-074 saves a run in Node; a player cannot yet keep a game. Save and load in the page: to and from a file, and in the browser keeping the last 3, by hand and when the page is hidden. Each save names the build that made it, and a save from any other build is refused with a message and an easy way to delete it and start a new game (Kim, 30 Oct and 8 Nov). Autosave at the moving round waits for a save under 0.5 s (VB-215).
Acceptance criteria:
- [x] `build.py` writes a build id into the page: a short hash of the sources it inlines, the same for the same sources, so `python3 build.py --check` still holds.
- [x] A page module (`src/page/saves.js`, in `src/page.json`) saves `{build, savedAt, label, save: Sim.save(st)}` gzipped (`CompressionStream`):
  - **Save** in the menu, and on `visibilitychange` to hidden, into IndexedDB, keeping the last 3;
  - **Save to file** downloads it as `.json.gz`;
  - **Load file** reads `.json.gz` or `.json`.

  The label names the scenario, seed, map, year and season, and the played pawn if any (VB-169).
- [x] The generation screen lists the stored saves (label, when saved) with **Continue** and **Delete**. The check is the page's: `Sim.load` keeps its format rule, so fixtures still load across builds.
- [x] A page save's file loads in `node tools/sim.js --load FILE` (the wrapper is unwrapped there), so a bug report can carry a played run.
- [x] Load regenerates the world from the save's seed and size, then loads the state: the run goes on as in Node, `st.player` included.

- 10 Nov 2026 (Kim, while it was built): four decisions that change the criteria above, which are ticked as built this way.
  1. Slots, not "the last 3": each archipelago (scenario, seed and size) has one auto slot, written when the page is hidden, and three
     slots written by hand. A slot is overwritten in place; no other history of saves is kept.
  2. Saves are a separate overlay, not part of the menu or of the generation screen.
  3. The page opens on a landing page with New archipelago (the generation screen) and Load archipelago (the Saves overlay). From a
     running game, the menu's Main menu leads there, and the game stays, paused, until another is generated or loaded (Back to game).
  4. An archipelago's saves can be deleted at once; a loaded file starts playing and takes no slot until it is saved.
  `design.md`'s Saving point was brought up to these on 10 November (VB-260).

Implementation (10 Nov 2026): `build.py` replaces `__BUILD_ID__` with the first 10 hex digits of the SHA-256 of the page before the
replacement, so the same sources give the same page. `src/page/saves.js` (in `src/page.json` after `page/notices.js`): a save is
`{build, savedAt, label, save: Sim.save(st)}` as gzipped JSON (`CompressionStream`). IndexedDB `village-builder` has two stores keyed
`<scenario>-<seed>-<cols>x<rows>:<slot>`: `saves` holds each slot's line (label, build, when, size, and what makes the archipelago) and
`blobs` its bytes, so listing never reads the bytes. `readSave` tells gzip by its magic bytes, else reads plain JSON, and refuses any
build but the page's; a bare `Sim.save` (from `tools/sim.js --save`) names no build and is refused as another build's. `Sim.load` keeps
its format rule. The loader's `build(seed, scenario, size, save)` regenerates the world and calls `Sim.load` in place of `Sim.seed`; a
played pawn is selected in place of the offer to play. `tools/sim.js --load` unwraps a page save, whatever its build. The simulation
does not run while the landing page or the generation screen is up (`src/page/speed.js`). No module of `src/sim` and no state changed.

Not built: a confirmation before Delete and Delete archipelago (they act at once); a save begun as the tab closes, not only hides, may
not finish; saving while a debug skip runs is refused silently.

Sizes, gzipped (Node, `tools/sim.js --save`): founders medium at year 1, 0.06 MB (1.30 MB of JSON); populous small at year 5, 1.15 MB
(6.06 MB); in the page, populous tiny seed 7 after 30 days 0.25 MB and after 130 days 0.41 MB. At medium-y5 it was 3.9 MB on
5 November, so an archipelago's four slots are about 16 MB at worst today.

`tests/browser-mobile.js` and `tests/browser-speed.js` pass run one by one, changed to start from the landing page (as `tools/shot.js`
and `tools/village-shot.js`). `npm run verify` as a whole was not run, nor were times taken (VB-260). By hand, once, in real Chromium
