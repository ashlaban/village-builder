# VB-097: Routes over regions (HPA*), if routes cost too much
Status: blocked
Priority: 3
Size: M
Arch: roads
Phase: implement
Design ref: World and scale (Uses of regions: hierarchical pathfinding for 1,000 pawns, HPA*, Botea, Müller and Schaeffer 2004: Agreed).
Goal: The design plans hierarchical pathfinding over the 169-tile regions. Routes today are searches up to 60 steps (VB-064), cached per pair of tiles in a cache that grows without bound (REVIEW.md, Performance). Build HPA* only if it is needed: measure first. Depends on VB-096 (terrain costs), so the abstract graph is built once with them; if it is not done, mark this blocked.
Acceptance criteria:
- [ ] HPA* trigger (cache measurement and bounding are VB-198): the share of simulation time spent in route search, and the route cache's size, on populous Large at seed 7 over 2 years. If routes take under 5% of simulation time with VB-198's bounded cache, report the numbers and stop there.
- [ ] Otherwise: an abstract graph of entrances on region borders, with intra-region costs precomputed per region and recomputed only for regions whose tiles change cost; long routes search the abstract graph and refine per region; routes within a region or to a neighbouring one stay direct.
- [ ] Paths are at most 5% longer than the direct search on 1,000 random pairs (reported); route time per query and memory reported before and after.
- [ ] Re-record the golden file if routes change and list the changed entries in the PR.
