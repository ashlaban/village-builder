# VB-169: Take control of a pawn
Status: needs-review
Priority: 2
Size: M
Arch: core
Phase: implement
Design ref: Commands, time steps and views (Direct control: Decided); answer 3 to VB-076: "Take control" on the pawn panel, the player chooses the next command from a list, the planner leaves the pawn alone until released.
Goal: The player, or someone debugging, takes over one pawn and gives it its commands. Depends on VB-167 and VB-168.
Questions: in `QUESTIONS.md`, "VB-169: take control".
Acceptance criteria (draft, as proposed):
- [ ] `a.controller` (absent, or `'player'`; `@state` documented, saved with the state, an invariant): the planner issues nothing for a controlled pawn (matching, interrupts, idling), but its needs go on as for any pawn: it eats, and at dark, when no command of the player's is under way, it goes home (proposed; see the question).
- [ ] `Sim.command(st, cmd)` issues a command with source `player`; `Sim.takeControl(st, id)` and `Sim.release(st, id)`; each writes a record event (`control`, `text` taken or released).
- [ ] The pawn panel: a "Take control" button; while in control, the commands to choose from: open jobs the pawn may take (role fit above 0, nearest first, up to 8), "Walk here" (the next tile clicked), "Go home", and "Release"; a refused command shows its reason in the panel.
- [ ] `tests/commands.js`: a controlled pawn is left alone by the planner for a day; a player's work command is carried out; after release the planner takes it up again. The browser smoke test takes control of a pawn and gives it a job.
- [ ] A screenshot of the panel in the PR; behaviour unchanged for pawns nobody controls (golden file unchanged).
- 2 Nov 2026 (VB-168): the `walkTo` verb accepts any tile that exists, since the planner's idle walks sometimes end on a river tile; "Walk here" should offer only tiles the walking rule opens (`passable` in `src/sim/routes.js`).
