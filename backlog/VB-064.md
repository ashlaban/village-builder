# VB-064: Routes: a safe cache key on Large maps, and no walks across water
Status: done (2026-10-30, pending)
Priority: 1
Size: S
Design ref: World and scale (Map size: Large 380 × 270); REVIEW.md, Defects.
Goal: `route` in `src/sim/agents.js` caches paths under `from * 100000 + to`. The Large map has 102,600 tiles, so two different routes can share a key and a pawn takes another pair's path. A route not found within 60 steps falls back to a straight line, across water if need be; expansion (VB-031, VB-033) will send pawns farther.
Acceptance criteria:
- [x] The cache key is `from * w.N + to` (or a nested map); no two pairs of tiles share a key on any map size.
- [x] `route` searches up to 60 steps as today, and when the target is not found, searches again up to 200 steps before falling back. Each fallback counts in `st.routeFallbacks` (`@state` documented). The cheap tests assert it stays 0 in their runs.
- [x] The dead test `j.kind === 'logs'` in `stepWork` goes (the kind is `wood`; `K.carry === 'logs'` already covers it).
- [x] A test on a Large map (380 × 270) finds two tile pairs whose old keys collide and checks that both get their own path.
- [x] Behaviour unchanged on the golden seeds: `npm run verify` passes and `tests/golden.json` is unchanged (no medium-map route is longer than 60 steps; if one is, list the changed entries and re-record).
