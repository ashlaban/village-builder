Goal: A merge whose only conflicts are in the backlog tables, the question and tuning files or a module's import block resolves without a person or an agent
Acceptance criteria:
- [x] The 48 merges since 15 Nov whose conflicts were only in bookkeeping or list files (`node docs/plans/VB-1618-split.js`, after the replay) are classified by file and kind: a row added on both sides, a row moved between sections on one side, a row edited on both sides.
- [x] `BACKLOG.md` and `BACKLOG_ARCHIVE.md` get a merge driver (`.gitattributes` and a committed setup that `npm install` runs, so a fresh clone, a worktree and the orchestrator's preflight all have it): both sides' row changes are kept and the tables come out as `tools/backlog.js sync` writes them; a row edited differently on both sides stays a conflict. `QUESTIONS.md` and `docs/tuning.md` likewise where the classification shows it pays.
- [ ] A conflict confined to a module's import block or export list (23 merges since 15 Nov touched one) resolves to the union of the names, by a format Prettier keeps one name a line or by a driver limited to those blocks; a conflict anywhere else in the file stays a conflict.
- [ ] Replayed with the drivers (in a scratch clone with `git merge` if `git merge-tree` does not run them): the merges since 15 Nov whose only conflicts were in these files and blocks merge clean; on five of them the result passes `tests/backlog.js` or `npm test`. Report the counts before and after.
- [ ] `docs/agents/worker.md`'s conflict rules say what is now automatic; a row in `docs/agents/changes.md`; `npm test` and `npm run verify` pass.
