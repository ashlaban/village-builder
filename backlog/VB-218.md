# VB-218: The pawn panel: goodwill balances and a holder's allowance
Status: done (2026-11-09)
Priority: 1
Size: S
Arch: kin-help
Phase: implement
Design ref: Exchange, goodwill and obligations (The gift: What the player sees, Agreed 8 Nov); VB-182's plan.
Goal: The player sees who owes whom and why: the pawn panel lists a pawn's largest balances and, for a holder, how much it would give each counterpart and what that is made of.
Acceptance criteria:
- [x] Under "Knows best" (`showRelations`, `src/page/words.js:189`), a list of up to 5 balances by size, from `Sim.goodwillOf`: "Owes Erik Larsson 34 rations" or "Is owed 12 rations by Anna Persdotter", rounded to whole rations (no reason or year: a balance is one number, Kim 8 Nov). A row focuses its pawn on click, as the relations rows do. No list when the pawn has no balance of a ration or more.
- [x] On a holder's panel, each row adds "would give up to N rations" toward that pawn's household, with `Sim.explainAllowance(st, giver, receiver)` (a read-only wrapper of `explain(allowance)`) on hover: each part's label and value ("Grain above the floor +120 · Own reserve −40 · Goodwill 0, from slice 4").
- [x] The page only reads: it calls the `Sim` API and writes nothing to `st` (the lint enforces it).
- [x] A check in the page tests (`tests/smoke.js` in jsdom, or `tests/browser.js`): after a run with gifts (populous 7, tiny map), a pawn with a balance shows its rows and a holder's row shows its allowance.
- [x] Cost: 0 ms of simulation; per panel refresh (every 0.25 s), one pawn's balances (at most 32) and at most 5 explanations.
- [x] A screenshot of the panel in the PR. Counters unchanged; in the golden file only `apiKeys.Sim` changes (the two new `Sim` functions),
  re-recorded and listed in the PR; `npm run verify` passes; `index.html` rebuilt.
