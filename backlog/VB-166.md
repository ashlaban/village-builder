# VB-166: A frame-time budget for the page, in headless Chromium
Status: blocked
Priority: 3
Size: S
Arch: yardstick
Phase: implement
Design ref: Vision and scope (up to about 1,000 pawns). External review of 2 November (`docs/review-external.md`).
Goal: VB-088 budgets the simulation in Node; nothing measures drawing. A page that simulates fast can still stutter when it paints 800 pawns and the map. Measure frame times in the browser so a costly drawing change is caught when it lands.
Deferred, Kim, 4 November 2026: skip the presentation budget for now. Rendering is intended to be GPU accelerated;
measurements on the current computer without a GPU do not establish the presentation budget. Resume when presentation
measurement is requested again. Functional browser checks and the simulation's own 12 ms pacing budget continue to run.
Acceptance criteria:
- [ ] `tests/frames.js` opens the built `index.html` in Playwright's Chromium as `tests/browser.js` does (PixiJS served from `node_modules` in place of the CDN, so no network); populous medium at seed 7, after the map is generated. Shared set-up moves to `tests/lib/` rather than being copied.
- [ ] It runs 20 s at 10× speed at the default zoom and 10 s zoomed out to the whole island, recording frame times with `requestAnimationFrame`; it reports frames per second, the median, 95th percentile and longest frame, and the share of frame time in simulation against drawing (the page's own timing, if exposed; otherwise frame time minus `Sim.advance`).
- [ ] Headless Chromium draws without a GPU, so the numbers are not a player's: the test records a baseline in `tests/frames-baseline.json` and fails when the 95th percentile exceeds twice the baseline; `--update` re-records it, only for an intended change.
- [ ] It runs in `npm run verify` if it takes under 45 s; otherwise as `npm run frames`, and `AGENTS.md` says when to run it (every task that changes `src/page/` drawing).
- [ ] The numbers at `HEAD` go in the PR and in this file.
