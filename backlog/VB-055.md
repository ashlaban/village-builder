# VB-055: TypeScript: real modules, typed state, a formatter and measures of width: survey and tasks
Status: ready
Priority: 3
Size: S
Arch: yardstick
Phase: implement
Design ref: none (test infrastructure)
Goal: A misspelt field (`hh.grian`), an argument in the wrong place or a holder of the wrong kind is silent in plain JavaScript until it misbehaves. Kim decided on 10 November (code review) to move the code to TypeScript, by a plan: real modules first, then `.ts` and types for the state, then strictness; and with the same sweep a standard formatter, and measures of a module's width in place of the cap on its length. Survey what the move touches and write the implement tasks. This replaces the first version of this task (`checkJs` with JSDoc and a hand-written `types.d.ts`), which sees little: every module is reached through `VB['<key>']`, which has no type, so no call between modules is checked.
Acceptance criteria:
- [ ] A survey, in this file: the modules of `src/manifest.json` and what each import and export becomes; the 16 late lookups (`later(...)`, "loads after this module") and whether each is a cycle between modules that stays or one to untie; the tests and tools that replace a module's function to time or count it (about 22 files: `tools/perf.js`, `tools/route-bench.js`, `tools/bench.js` and the like), since an export cannot be reassigned: one hook for them all (a registry of timed functions, or the build's own instrumenting), chosen and justified; the page script (`src/page/*.js`, one closure sharing about 340 names), and whether it is left as it is at first; the tools that parse the source (`tools/writes.js` with acorn, the lints by line, `tools/wrap.js`) and what each needs.
- [ ] Step 1 as implement tasks, each of size S or M where it can be, behaviour unchanged and `tests/golden.json` with it: `import` and `export` in place of the `VB` namespace and the manifest's order, still JavaScript; a bundler (one dev dependency) in place of `build.py`'s inlining, with `index.html` still one self-contained file and `--check` kept; the loader of the 96 tests and tools changed in one place; the dependency check (`tests/dependencies.js`, VB-230's layers) read from the import graph.
- [ ] Step 2: the files become `.ts`, run by Node as they are (type stripping; name the least Node version and what the Checks workflow uses) with erasable syntax only, so nothing but the page's bundle is built; the state's shapes as types (`State`, `Pawn`, `Household`, `Farmstead`, `Village`, `Job`, `Agent`), made from the 77 `@state` tags, which then go or point to the type; `st` is plain data as a type (no function, no class instance); a holder in `sim/stores` is a union of three (VB-237). `tsc --noEmit` in `npm test`.
- [ ] Step 3: `strict` module by module, with a baseline of errors that only falls, as the lint's.
- [ ] The formatter (Kim, 10 Nov): one sweep with a standard formatter at a stated width, in a commit of its own listed in `.git-blame-ignore-revs`, in the same task that renames the files, so every file is rewritten once; `tools/wrap.js` and the lint's 160 columns go. Measured on 10 November at width 120: `sim/relations.js` 399 lines becomes 667, `sim/heirs.js` 400 becomes 644, the simulation and generation modules 8,554 become 14,100.
- [ ] In place of the cap of 400 lines a module (Kim, 10 Nov): the lint holds a module's exports to 15 and a function's formatted length to 60 lines, each with a baseline that only falls; no cap on a module's length. The tasks state today's numbers and which modules and functions start in the baseline (exports on 10 November: `sim/rules` 42, `sim/records` 42, `sim/relations` 32, `sim/herds` 28, `sim/agents` 26, the median 8; `heirRanking` and `movingRound` among the functions). `AGENTS.md` and the refactor rules of `BACKLOG.md` ("stays under 400 lines") follow.
- [ ] When: the tasks say which open tasks they must not run beside (every task that edits `src/`), and name the slice boundary at which step 1 runs. The cost named: files and lines touched, the agent sessions expected, and what `npm test` and verify gain in time (`tsc` took 2 s over the modules on 10 November).
- [ ] `docs/architecture/target-v2.md` (its interface sketches are already TypeScript-style types), `modules.md` and `AGENTS.md` (Finding things; Conventions) get a line each on what changes, written by the tasks, not here.
