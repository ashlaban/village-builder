# VB-116: Job kinds as one record each, and roles that rank types of work
Status: done (2026-10-30)
Priority: 2
Size: M
Arch: work
Phase: implement
Design ref: Economy and jobs (Jobs, owners and roles: Role priorities). Jobs review, 30 Oct 2026 (second pass, `REVIEW.md`, "Work and jobs, second pass").
Goal: One job kind lived in nine places across four files: `KINDS` and eight role tables in `src/sim/rules.js`, posting, urgency and the idle label in `src/sim/jobs.js`, the work spot, completion, delivery and carry destination in `src/sim/agents.js`, and the job's name in the page script. Every new kind also added a number to all eight roles. The work arch and the new concrete jobs (fishing, gathering, milling, village work days, crafts) each add kinds, so adding one should be cheap and hard to get wrong.
Acceptance criteria:
- [x] `src/sim/kinds.js` holds `KINDS`, one record per kind: verb, go, back, name (settlers panel), label (idle line), anim, hours, type of work, field, inside, carry and its destination (`to`: door, woodpile or barn), row pace, and the functions `spot`, `urgency`, `done` and `deliver`. `sim/agents` and `sim/jobs` read them; the switches on `j.kind` are gone.
- [x] Roles rank seven types of work (tilling, tending, harvest, threshing, wood, upkeep, household) in `ROLES[role].work`, with `except` for single kinds; `sim/kinds` fills in `ROLES[role].prio`, so readers of `prio` are unchanged. The derived priorities equal the old table for every role and posted kind.
- [x] Behaviour unchanged: `npm run verify` passes and `tests/golden.json` is unchanged; `Sim` keeps its keys (`KINDS` now comes from `sim/kinds`).
- [x] `tests/kinds.js`: every kind has its labels, hours and a type some role ranks; carried kinds have a destination and a delivery; `prio` follows `except`, then `work`.
- [x] CLAUDE.md says what a new kind touches.
