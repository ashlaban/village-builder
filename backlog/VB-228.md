# VB-228: Refactor: split sim/commands: each domain registers its own verbs
Status: done (2026-11-18)
Priority: 1
Size: M
Design ref: none (code structure). `docs/architecture/target-v2.md`, sections 3.2 and 4.1 (commands).
Goal: `sim/commands` holds every verb's body, so it imports `sim/agents`, `sim/kinds`, `sim/exchange` and `culture` at load and looks up nine later modules through `later()`, at 17 call sites. Those 16 edges are why 27 modules form one cycle (`docs/architecture/ownership.md`, section 4). Each domain should register its verbs at load, as it registers rules, so the kernel's command module knows no domain.
Acceptance criteria:
- [x] `sim/commands` gains `register(verb, {check, run})`, at load only and sealed with the rules registry at the first seed or load; a duplicate verb throws. `issue` is unchanged: check, then run, or nothing.
- [x] Each verb's `check` and `run` move, verbatim, to the module that carries it out (`marry` to `sim/lifecycle`, `serve` to `sim/service`, `give` to `sim/exchange`, and so on); a verb that only wraps an act of `sim/agents` moves there.
- [x] `sim/commands` imports no domain module and has no `later()`; it loads before every module that registers a verb. `tests/dependencies.js` drops the dispatcher's exemption and still allows `issue` from any module.
- [x] `tools/writes.js` reports no strongly connected component through `sim/commands`; `ownership.md`, section 4, is updated with its output, and says which cycles remain.
- [x] `tests/commands.js` still holds that only a verb calls the act it wraps, now reading the verbs from their modules.
- [x] Refactor rules of `BACKLOG.md`: behaviour unchanged, `node tools/same.js --base REF` prints `same`, `tests/counters.json` unchanged, `npm run verify`'s hard checks pass, its targets reported with their residuals.
- [x] Added 15 Nov (VB-433's criteria): `sim/commands` is under 700 lines and within its export baseline, and the baselines fall with it.
