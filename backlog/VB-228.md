# VB-228: Refactor: each domain registers its own verbs
Status: ready
Priority: 3
Size: M
Design ref: none (code structure). `docs/architecture/target-v2.md`, sections 3.2 and 4.1 (commands).
Goal: `sim/commands` holds every verb's body, so it imports `sim/agents`, `sim/kinds`, `sim/exchange` and `culture` at load and looks up eight later modules through `later()`. Those 16 edges are why 27 modules form one cycle (`docs/architecture/ownership.md`, section 4). Each domain should register its verbs at load, as it registers rules, so the kernel's command module knows no domain.
Acceptance criteria:
- [ ] `sim/commands` gains `register(verb, {check, run})`, at load only and sealed with the rules registry at the first seed or load; a duplicate verb throws. `issue` is unchanged: check, then run, or nothing.
- [ ] Each verb's `check` and `run` move, verbatim, to the module that carries it out (`marry` to `sim/lifecycle`, `serve` to `sim/service`, `give` to `sim/exchange`, and so on); a verb that only wraps an act of `sim/agents` moves there.
- [ ] `sim/commands` imports no domain module and has no `later()`; it loads before every module that registers a verb. `tests/dependencies.js` drops the dispatcher's exemption and still allows `issue` from any module.
- [ ] `tools/writes.js` reports no strongly connected component through `sim/commands`; `ownership.md`, section 4, is updated with its output, and says which cycles remain.
- [ ] `tests/commands.js` still holds that only a verb calls the act it wraps, now reading the verbs from their modules.
- [ ] Refactor rules of `BACKLOG.md`: behaviour unchanged, `tests/golden.json` and `tests/counters.json` unchanged, `npm run verify`'s hard checks pass, its targets reported with their residuals.
Notes:
- 9 Nov 2026, from the review of target-v2 against the code (Kim's decisions of that day, target-v2 section 8). Of 20 verbs, most are issued by the module that also carries them out, so this moves code home; it does not change who may issue what.
