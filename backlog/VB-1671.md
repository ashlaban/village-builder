# VB-1671: Task footprints: one guide to writing a task, and a Touches line naming the functions it edits
Status: ready
Priority: 2
Size: M
Design ref: docs/plans/VB-1671-conflicts.md; BACKLOG.md, How this backlog works; docs/agents/worker.md, project-manager.md; .claude/agents/vb-task.md
Goal: Every new task names, in a Touches line, the functions (or tables) of each module it will edit, written from one guide that every writer of tasks follows, so a tool can tell which tasks may run side by side
Acceptance criteria:
- [ ] One guide to writing a task, `docs/agents/tasks.md`, for every place a task is written: the orchestrator, a sub-agent's `task` note, the project manager, a plan task, the reviewer, a session with Kim. It gives the header lines and their order, how to state the goal and criteria, size, `Waits for:` and the `Touches:` line below. `AGENTS.md`, `BACKLOG.md` (How this backlog works), `docs/agents/worker.md`, `project-manager.md`, `reviewer.md` and `.claude/agents/vb-task.md` (step 5) point to it, not restate it.
- [ ] A `Touches:` line after `Design ref:` names what the task will edit, at function level (`docs/plans/VB-1671-conflicts.md`: 41% fewer false alarms than file level, no conflict missed): a module key or a path, with the module-level functions or tables it edits in brackets, and `new` for a module it creates, e.g. `Touches: sim/jobs (allot, lookForWork); page/words (showPawn); tests/jobs.js; new sim/wells`. A module's import block, export list and `@sys` header are implied. List and bookkeeping files are not named while they are lists (VB-1406). `Touches: unknown (<reason>)` is allowed for a plan task, or when the writer cannot tell.
- [ ] `tests/backlog.js` checks the line's format, and requires the line on a task that is ready from VB-1674 on; it warns, without failing, when a named module does not exist and is not marked `new`.
- [ ] `tools/backlog.js new` takes `touches=`; the inbox `task` note takes `touches=`, and `apply` writes it.
- [ ] A task without the line gets it from the agent that takes it, before its first edit (`vb-task.md`, step 3), so the line fills in as tasks are worked; no bulk backfill. The free-text "runs beside" notes in older tasks stay; the guide says new tasks write the `Touches:` line instead.
- [ ] A row in `docs/agents/changes.md` (an agent instruction change); `npm test` and `npm run verify` pass.
