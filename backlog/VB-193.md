Goal: The late game's costs do not show at year 2, where `tests/perf.js` looks. Measured for the plan on 3 November (populous small at seed 7, this repository's container): the moving round takes 485 ms in one call at year 40 and 897 ms in its place in year 41, against 37 ms at year 5; 13 of 30 midnights take over 50 ms at year 40, against 2 at year 5; and the save is 29 MB of JSON. Reaching year 40 takes 270 s, and year 60 on a medium map perhaps 90 minutes (estimated from 190 ms a game day at year 2). Saves made once and loaded in under a second give every check a late state. In the session that ran VB-181 (3 November) it was chosen to keep them on an orphan branch, `fixtures`, so main's history stays small though they are remade after most behaviour changes.
Acceptance criteria:
- [x] `tools/fixtures.js` knows four fixtures, all populous at seed 7: `small-y5`, `small-y40`, `medium-y5` and `medium-y60` (the late reference, about 1,000 living). Each is a gzipped save (`Sim.save`) in `tests/fixtures/` (gitignored), with a stamp `<name>.json` beside it: the commit it was made at, the save's `format`, the SHA-256 of `tests/golden.json`, its year, living pawns, pawn records and events in `st.record`, and the minutes it took to make.
- [x] Commands:
  - `make [name...]` builds the named fixtures (all by default), one per core in parallel;
  - `status` prints each fixture as missing, fresh, or stale (its golden hash or format differs from the working tree's);
  - `fetch` gets them from `origin/fixtures` (`git fetch origin fixtures`, then `git show` per file), and does nothing, with a notice, without a network;
  - `publish` replaces the branch with one orphan commit holding the four saves and their stamps, and pushes it with `--force-with-lease`. This is the only force-push the project makes: the branch keeps no history by design, and `BACKLOG.md`'s header says so.
- [x] `tests/lib/fixtures.js` exports `loadFixture(name)` → `{st, stamp, stale}` or `null` when there is none, fetching first if it is missing. It generates the world from the save's seed and size and loads the state, so later checks need no copy of this code.
- [x] `tests/fixtures.js` in `npm run verify`: each fixture present loads, advances one game day and passes `checkState` (`tests/lib/invariants.js`); a missing fixture without a network is skipped with a notice, not a failure; a fixture whose `format` differs from the build's fails with "remake the fixtures".
- [x] `npm run nightly` (`tools/nightly.js`) fetches the fixtures, remakes the stale and missing ones in the background, publishes them, and prints what it did. Later tasks add their steps to it (VB-194's bench, VB-163's full bands). `BACKLOG.md`'s header says the nightly run starts with it. If `medium-y60` takes over 2 hours to make, the PR says so and proposes how often to remake it.
- [x] The numbers at `HEAD` in this file: per fixture, the minutes to make, MB of JSON and gzipped, living, pawn records and events in the record.
- [x] `AGENTS.md`, Commands: the fixture commands, and that a check or a task needing a late state uses `loadFixture`.
- [x] When done: sets VB-194, VB-196 and VB-198 `ready`, and VB-088 if VB-192 is done too.
Cost: about 6 MB of disk per small fixture and an estimated 15 to 20 MB for `medium-y60`, gzipped; making all four takes an estimated 90 to 100 minutes on one core per fixture, nightly and only when stale.

Implementation notes (5 November 2026):
- Impact: tools and test infrastructure only. Reads `VB.gen`, `Sim.seed/advance/save/load`, `sim/saves.FORMAT`,
  `tests/golden.json` and Git provenance; writes ignored fixture files and their stamps. No simulation or page state fields,
  owners, commands, rules, counters or runtime dependencies are added. Simulation goldens and work-counter baselines stay unchanged.
- `tests/lib/fixtures.js` owns the four definitions, freshness, checksums, fetch and load. `tools/fixtures.js` supplies bounded worker
  processes and publication through Git objects, with no checkout or index operations. Publication targets only `refs/heads/fixtures`,
  uses no parent for its commit, and leases the exact remote head (including an absent branch).
- `tests/fixture-tools.js` uses an isolated local bare remote for freshness, missing/offline handling, damaged saves,
  incompatible formats, replacement orphan commits, a competing publisher, and preservation of an uncommitted worktree and index.
- All fixtures are populous, seed 7; years count complete years advanced from the scenario's 06:00 start.
  `make` refuses uncommitted simulation source/golden changes so the stamp's commit identifies the simulation actually used.
- Verification runner: real Chromium checks run individually before the parallel headless checks. The first full run passed all
  non-browser checks but timed out in clicks with simultaneous software-rendered browsers on this two-CPU-quota runner;
  the unchanged browser smoke test passed in isolation. No browser assertions or timeouts were relaxed.
