# VB-1689: Invariant: a verb's check holds alike for a played and an unplayed pawn
Status: done (2026-11-26)
Priority: 2
Size: S
Arch: plans
Phase: implement
Design ref: docs/review-principles-2026-11-24/synthesis.md (Invariant catalogue, M8); tests/commands.js; src/sim/player.js; design.md, Principles for decisions (Every act is a pawn's); docs/architecture/target-v2.md, principle 15
Touches: tests/commands.js; sim/player
Goal: The player has what its pawn has, no more and no less: a verb any pawn may use is checked the same for the played pawn, and a verb only the player has is named with its reason.
Acceptance criteria:
- [x] In `tests/commands.js`, verbs whose only source is the player are listed against an allow-list with a written reason each (the one in `sim/player.js` first), and a new one fails the check.
- [x] Each registered verb's check is run twice on a constructed state, the played flag swapped, with the same result; a difference fails the check.
- [x] Each field of `st.player` is listed with why a pawn could not hold it; one a pawn could hold (VB-1645's sleep, VB-680's wishes) gets a task.
