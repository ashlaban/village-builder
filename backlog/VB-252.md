# VB-252: The seasonal plan: the culture's year as a template, golden unchanged
Status: ready
Priority: 2

Goal: Layer 1 of how a holder chooses (design.md, section 7): the culture's year as a template. Today's order and targets are constants spread over the kinds and the role rankings. Put them in one table per culture, which the review reads, with today's values, so that the order (VB-023), a head's foresight (VB-254) and the player (VB-253) each change one row.
Acceptance criteria:
- [x] A template per culture, declared as rules of `VB['sim/registry']` (declared before the first seed or load; never in saved state): for each season, the routines in their order, and a target for each store (the woodpile by season, hay in winters, seed, fields per hand). Its first values are today's (`woodTarget`, `woodWinter`, `ENOUGH`, `fieldsWanted`'s numbers), the same for every culture.
- [x] The seasonal plan, a second plan per household beside the standing one (`kind: 'season'`), made at each season's first review from the template: its steps are the season's routines in order; the plan's targets (VB-248) are copied from it. The review reads steps and targets from the plan, never from the template directly, so a later change to one household's plan touches no other.
- [x] The order is recorded and not yet enforced beyond what the role rankings do today: `tests/golden.json` unchanged. (VB-023 enforces the first order: sowing before the next hoeing.)
- [x] The template's value read in an inner loop is compiled to an array at the season's turn (rule 6); `value()` allocates nothing.
- [ ] `node tools/sim.js --household N --report plans` prints a household's plans: targets, steps, next review. Invariants: one seasonal plan per occupied household, of the current season. `npm run verify`'s hard checks pass, its targets reported with their residuals.
Cost: one small record per household a season.

Implementation notes:
- `src/sim/plans.js`: the template is six rules of `VB['sim/registry']`, declared at load (owner `sim/plans`, ctx `{culture, season, routine}`):
  `year.order` (a routine's place in the season, -1 when it is not done then; base `ROUTINES`, one list of kinds per season), `year.wood` (by
  season: `woodTarget`, `woodWinter`, `woodWinter`, `woodTarget`), `year.woodSecond` (`woodTarget * 0.4`), `year.hayWinters` (2, the old
  `ENOUGH`), `year.seed` (`seedPerField`), `year.perHand` (`FIELDS.perHand`). The same for every culture (no contribution yet).
- `templateOf` compiles it per culture at the first need in a season (the season's turn): the woodpile's goal for all four seasons, the season's
  other targets, and its steps, sorted by `year.order`; 8 + 22 rule reads per culture a season, one ctx object reused. The compiled form is a
  WeakMap cache keyed by the state, derived from the rules only: never saved; a loaded run compiles it again.
- `st.plans.seasons`: a Map of household id to its seasonal plan `{holder, kind: 'season', year, season, made, steps}`, made with the standing
  plan (`makePlan`, and `fillPlans` for an older save) and again at the standing plan's first review in each season (`reviewed`), when the
  standing plan's targets (`wood`, `woodSecond`, `hayWinters`, and the new `seed` and `perHand`) are copied from the template. Reviews within
  the season no longer rewrite the targets: they read them from the plan (`fieldsWorkable(st, hh, T.perHand)`; `seedNeed` reads
  `plan.targets.seed`, `ECON.seedPerField` before a plan exists). Dropped with the standing plan (`dropPlan`).
- The order is recorded only: nothing reads `steps` yet (VB-023 will).
- `tools/sim.js --report plans` (every live household) and `--household N --report plans`: culture, targets, reservations, next review and
  cadence, last review day, the seasonal plan's season and steps.
- `tests/lib/invariants.js`: one seasonal plan per live household, its steps existing kinds, of the current season once the standing plan has
  been reviewed in it (never of a later one); the targets `seed` and `perHand` present. `tests/plans.js`: four new sections (the rules and
  their values for cultures -1, 0, 1; seasonal plans from the start; a household's changed target and steps stand through a review and touch
  no other, the next season's first review makes them again from the template, compiled once per culture; dropped with the plan, filled at load).
