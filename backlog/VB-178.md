# VB-178: Refactor: ties and attitudes only through `sim/relations` and `culture`
Status: done
Priority: 2
Size: S
Arch: ownership
Phase: implement
Design ref: none (code structure). VB-172's map, sections 5.6 and 7.4; Kim's answer 1 of 3 November (`QUESTION_ARCHIVE.md`, "VB-172: the ownership map").
Goal: `pawn.ties` has five writer modules: talk (`sim/relations`), gifts (`help.js:37`), marriage and death (`lifecycle.js:117`, `30`), the daily turning of contacts into ties and the kin floor (`lifecycle.js:234-241`), the seeding of ties (`society.js:35-40`) and a newborn's (`births.js:29-30`). VB-127 caps ties at 150 a pawn; with five writers the cap would leak. Give ties one owner before VB-127.
Acceptance criteria:
- [x] `sim/relations` owns `pawn.ties` and `pawn.rel`, with operations to strengthen a tie, set it (marriage, the kin floor) and drop a pawn's ties (a death); the daily rule of contacts and ties moves out of `dailyLife` into `sim/relations` or `sim/society`.
- [x] The culture fields of a new pawn (`att`, `anc`, `advocate`, `prestige`, `interest`) are set by one function, used by seeding (`society.js`) and births; `culture` owns `att`, `anc` and `advocate`.
- [x] `node tools/writes.js --field pawn.ties` (and `pawn.rel`, `pawn.att`, `pawn.anc`, `pawn.advocate`) lists only the owner and that one function, apart from the save codec.
- [x] Refactor rules of `BACKLOG.md`: behaviour unchanged, `tests/golden.json` unchanged, `npm run verify` passes.

Implementation report (6 November 2026):
- Relations now owns all initialization and mutation of ties and relationship
  records. Added `initRelations`, `setTie`, `strengthenTie`, `dropTies` and
  `dailyTies`; Society re-exports the unchanged pair encoding API from Relations.
- The daily tie update moved from lifecycle verbatim, including its counters,
  contact accumulation, decay, kin floor and weak-tie removal. Death retains the
  dead pawn's own historical ties as before and drops contacts' reciprocal ties.
- Culture's `initPerson` is shared by scenario seeding and births; it receives the
  same seeded or inherited attitude and copies its anchor. Culture's `advocate`
  also handles argue/rally. These internal wiring methods are non-enumerable,
  preserving the public enumerable Culture API checked by the golden file.
- Impact: no new module, saved field, random draw or pass. Daily work stays
  living pawns + their existing ties + the day's contacts + close kin. Five
  non-owner modules no longer mutate ties; the duplicate culture initialization
  is gone. The ownership baseline falls by 33 write sites (124 to 91).
- `tools/writes.js --field` for ties, rel, att, anc and advocate reports only
  the corresponding owner; no new exemption or baseline allowance was added.
- `npm test`: 68 scripts passed. Golden-state verification passed unchanged;
  `tests/golden.json` and `tests/counters.json` were not re-recorded.
- Architecture/design review, explicit plan and five-task sequence:
  `docs/review-2026-11-06.md`. Visual smoke captures in `docs/img/vb178/`.
- `npm run verify`: 81 scripts passed in 401.5 s using system Chromium and
  the documented software-render fixture mode. All four late-game saves were
  checked, with no missing fixtures; history's 14 counters pass, including known
  excesses. Invariants and saved/loaded continuation match unbroken runs.
