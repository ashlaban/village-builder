# VB-231: Refactor: the customs in force, read from the kernel layer
Status: done (2026-11-22)
Priority: 3
Size: M
Design ref: none (code structure). `docs/architecture/target-v2.md`, principle 12 and section 3.1 (Kim's decision 27).
Goal: Custom is read through one door, and the door is in the kernel layer because every layer asks it (target-v2, principle 12 and 3.1; Kim, 9 November). Today `sim/claims`, `sim/territory`, `sim/records`, `sim/commands`, `sim/opportunities` and `sim/lifecycle` read practice arrays themselves, through `Culture.DIMS` and `Culture.IDX`. Give them the door, and leave `culture` as the only writer.
Acceptance criteria:
- [x] A kernel-layer read, `inForce(st, key, at)` (a settlement or a tile), gives the option in force for a custom, from the same arrays as today. It allocates nothing; it lives in a module loaded before its readers that imports nothing social (a new `sim/customs`, or the part of `src/culture.js` that only reads).
- [x] The readers in `sim/claims`, `sim/territory`, `sim/records`, `sim/commands`, `sim/opportunities` and `sim/lifecycle` ask it; outside `culture` and the door, no module under `src/sim` indexes a practice array (a lint, or `tests/ownership.js`, checks it).
- [x] `culture` stays the only writer of customs, attitudes and drift (`src/owners.json` unchanged or tightened).
- [x] `tools/rules.js`, or a small `tools/customs.js`, lists each custom key's readers (target-v2 4.4).
- [x] Refactor rules of `BACKLOG.md`: behaviour unchanged, `node tools/same.js --base REF` prints `same`, `tests/counters.json` unchanged, `npm run verify`'s hard checks pass, its targets reported with their residuals.
