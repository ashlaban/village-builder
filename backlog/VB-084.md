# VB-084: A 30× speed and an uncapped speed
Status: done
Priority: 3
Size: S
Design ref: Time and calendar (Speeds: pause, 1×, 3×, 10×; Pace of play); Open questions (Faster speeds or skipping nights).
Goal: At 10× a year takes about 4 minutes, so a 150-year run is about 10 hours at full speed, much of it uneventful. The simulation takes about 0.2 s per game day on populous medium, so 30× costs about 13% of a core.
Acceptance criteria:
- [x] A 30× speed.
- [x] An uncapped speed: each frame advances the simulation as far as a frame budget of 12 ms allows, so the speed is set by the machine; the speed buttons show it as "Uncapped" with the speed reached (for example "Uncapped (41×)").
- [x] The clock and the picture stay in sync at every speed (VB-002).
- Presentation frame-rate acceptance is deferred by Kim (4 November 2026): skip the presentation budget for now;
  it needs an accelerated renderer. This is no longer a completion gate for VB-084 (see VB-166).
- [x] An option in the speed controls lets the simulation keep running while the game's tab or window is not in focus (Decided, 30 Oct; `design.md`, Running in the background); off by default.
Notes / questions:

Implementation, 4 November 2026:
- Impact: page-only timing in `src/page/speed.js`, read by `page/animate` and controlled by `page/input`.
  Reads `st.t` and invokes the existing `Sim.advance`; adds no simulation fields, owners, random draws or save data.
  No changes to the simulation's rules, golden file or work counters.
- Added 30× and Uncapped controls, keyboard shortcuts 4 and 5, and pause/resume remembering either mode.
  Uncapped checks a 12 ms wall-clock budget between ordinary 0.1-hour steps; an individual expensive step cannot be interrupted.
  Its label samples actual game progress per elapsed wall second every half second.
- Background running is off by default. Focus/visibility changes select one driver: visible frames or a 100 ms background timer.
  Each background interval is capped at 250 ms; returning never replays accumulated time. Browsers can throttle hidden timers.
  Editing form controls no longer triggers game shortcuts. The controls wrap at phone widths.
- Verification: `tests/speed.js` checks fixed rates, budget boundaries, an over-budget indivisible step, measured speed,
  pause, focus/visibility, opt-in background progress and bounded catch-up. The page smoke checks the clock at
  1×, 3×, 10×, 30× and Uncapped. `tests/browser-speed.js` checks the real page at populous tiny, seed 7,
  including keyboard resume, background progress, full-date clock synchronisation, visible pawn positions and mobile fit.
  It no longer measures frame times: presentation performance is deferred, rather than inferred from software rendering.
- Initial checks: `npm test` passed all 63 scripts (76.0 s); `npm run verify` passed all 73 scripts (188.0 s), including
  golden state, save/load equivalence, invariants and both browser checks. `index.html` is rebuilt. The golden and counter baselines
  are unchanged. Desktop and 390 px mobile screenshots were inspected; the speed controls fit both layouts.
